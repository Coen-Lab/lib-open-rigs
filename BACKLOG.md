## lib_zapit into open-rigs[zapit] (agreed 26 Nov 2026; open, after the Zapit cutover)

Why: since the cutover, Zapit runs as ZapitDaq (`OpenRigs.Zapit`, `OpenRigs.Opto.ZapitBonsai`) in the workflow, with a control app's agent building the bank and the fits through `lib_zapit`. `lib_zapit` still lives in the Zapit app's repo (folder `lib_zapit/`, its own `pyproject.toml` `lib-zapit` 0.1.0, `uv.lock`, tests), so every machine that runs that control app keeps a clone of the Zapit app only for that folder, and the agent restarts whenever that repo moves, GUI commits included. The bank's maths and the C# that reads the bank (`ZapitBank`, `ZapitDaq`, `ZapitSetupCapture`, `docs/zapit-setup-protocol.md`) belong together: one repo, one CI, the contract fixture (`src/OpenRigs.Zapit.Tests/Data/make_fixture.py`) regenerated in-repo. The Zapit app's window (PyQt6, ZeroMQ server, port 1488) is replaced by the control app's Zapit panel; its retirement, and the control app's switch to this package, are steps in their own backlogs.

Before step 1, the Zapit app's `zapit-native` branch merges to its main (26 Nov 2026, at the cutover: its tip was 5851890, 7 commits ahead of main, with `with_found_area`, `tests/test_target_area.py` and the rig config's dropped `earlyStopLeadSeconds`). ### Gate: the licence (decide before step 1)

The Zapit app's `LICENSE` is LGPL-2.1, as upstream Zapit-Optostim/zapit's is, but its `README.md` ("Licence and credit") and `lib_zapit/pyproject.toml` say GPL-3.0(-or-later). `waveforms`, `transforms` and the calibration scheme are ports of upstream's design, so the moved code keeps upstream's licence; this repo is BSD-3-Clause and public. Default unless decided otherwise: keep `src/open_rigs/zapit/` under LGPL-2.1 with its own `src/open_rigs/zapit/LICENSE` (copied from that app's `LICENSE`), a header line in `src/open_rigs/zapit/__init__.py` saying so, and a section in `THIRD-PARTY-NOTICES.md` naming upstream (Maja Skretowska and Rob Campbell, SWC) and the folder. If the code turns out to be GPL-3.0 after all, stop: it cannot go into a BSD package, and `lib-zapit` becomes its own repo instead.

### Risks

- The `cv2` swap: an environment that moves from `opencv-python-headless` to this extra's `opencv-python` has two wheels writing the same `cv2` folder. If the removal runs after the install, `cv2` is broken: check `import cv2` on the first consumer; the fix is `uv sync --locked --reinstall-package opencv-python`.
- Linux CI is new for this code (the Zapit app's CI never ran `lib_zapit/tests`; it ran only locally on Windows). Watch `test_zapit_sample`/`test_zapit_target_area` (ORB registration, Otsu) and the sample-for-sample waveform reference on Linux and Python 3.11's numpy. Mark a test Windows-only only with the cause found; never loosen a locked reference to pass. `opencv-python` on ubuntu may need `libgl1`.
- Two readers of rig.yml's `zapit` block (`open_rigs.components.zapit.Zapit` and `open_rigs.zapit.rig_config`) now sit in one repo and can be held equal by a test. That is a follow-up, not part of the move.
- Bank records: the index's `lib_zapit` value names a Zapit-app commit before a consumer moves to this package and a lib-open-rigs commit after. Say so in `docs/zapit-library.md`. Readers check presence only.

### Rollback

Step 1 is additive: revert its merge commit (`git revert -m 1`); nothing depends on it until a consumer pins it.

The consuming apps' steps (the Zapit app's freeze and retirement, the control app's switch to `open-rigs[zapit]`, their docs and rollout) live in their own backlog.
